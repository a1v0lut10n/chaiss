# Release 0.7.1 to crates.io

- **When:** 2026-11-11 17:01:54 local
- **Type:** execution
- **Project:** chaiss

## Context

Hours after 0.7.0 shipped, Hans reported that every Gemini turn failed
with `OpenAI responses API returned error status: 404 Not Found`, and
while building noticed `aws-sdk-bedrockruntime` compiling for a chess
app that uses no AWS service.

## Details

The 404 came from the 0.7.0 dependency refresh: `llm` 1.3.7 -> 1.3.8,
whose OpenAI backend posts every request to the Responses API at
`<base_url>/responses` instead of `chat/completions`. chaiss reaches
Gemini through that backend with Google's OpenAI-compatible base URL,
which serves `chat/completions` only. Upstream graniet/llm#121 had
reported the same break for llama.cpp and LM Studio in April and was
closed with a workaround (use the generic `OpenAICompatibleProvider`
directly); master still posts to `/responses`. The old requirement
`llm = "1.3.7"` also meant every `cargo install chaiss` without
`--locked` had resolved to the broken crate since April.

CHAI-0058 (PR #87) pinned `llm = "=1.3.7"` and, in a second commit,
turned the crate's default features off: `default` enabled its CLI,
and the CLI enabled `full`, every backend the crate has. 98 crates
left the lockfile (816 to 718), the Bedrock SDK among them. Moving to
the generic provider or the native Google backend is recorded as the
follow-up, to be done with a live game.

The day also brought a GitHub runner outage (actions/runner-images
#15296): the Ubuntu 26.04 image could not resolve the apt mirrors from
13:48 UTC, and every run failed in "Install System Dependencies". The
step turned out to be unnecessary: wayland-sys is built with `dlopen`,
winit's X11 and xkbcommon bindings load at run time, nothing uses ALSA,
and libssl with pkg-config is preinstalled. PR #88 removed it. Two
lessons on the way: re-running failed jobs reuses the original
workflow snapshot, and a reopened PR may still run the branch's
workflow, so the journal PR had main merged into it to pick up the fix.

Release PR #89 bumped both crates 0.7.0 -> 0.7.1 (patch: a regression
fix and a dependency trim) and closed the changelog section. Published
chaiss-core then chaiss with `SQLX_OFFLINE=true`; tag `v0.7.1` and the
GitHub release carry the changelog section.
