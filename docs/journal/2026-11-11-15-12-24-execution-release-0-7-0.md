# Release 0.7.0 to crates.io

- **When:** 2026-11-11 15:12:24 local
- **Type:** execution
- **Project:** chaiss

## Context

Two work streams had landed since 0.6.0: on this Linux machine the
engine-checked predicted lines (CHAI-0051), the renderer failure
message (CHAI-0055) and the Send button border (CHAI-0056); from WSL
the egui 0.37 upgrade with colour emoji (CHAI-0052), the X11 window on
WSL (CHAI-0053) and the widget theme through `StyleProvider`
(CHAI-0054), plus colap 0.5 without default features (#76). Hans asked
for a release once the housekeeping was done.

## Details

Housekeeping first. The tinted chat emoji seen on this KDE/Wayland
desktop got its own ticket, CHAI-0057 (PR #84), with two fontconfig
leads recorded: a Source Code Pro install that carries an outline 🤖
and outranks Noto Color Emoji, and a CBDT-only emoji font for 👤. The
suspicion that rustemo was a leftover dependency was checked and
dismissed: chaiss has not declared it since the colap facade, and what
remains is colap 0.5's own parser runtime and build-time compiler,
which only colap can drop.

Release PR #85 bumped both crates 0.6.0 -> 0.7.0 in lockstep, folded
the `[Unreleased]` section (which had two sets of headings from the two
streams) into one, put a ticket on every entry, noted CHAI-0057 as a
known issue, and refreshed the lockfile to the latest compatible
versions (no yanked crates; egui stays on 0.37.0, colap on 0.5.0).
Minor bump: the egui upgrade, the theme, the engine-checked lines and
the colap switch are all behaviour changes. Gates clean, 80 tests.
Published chaiss-core then chaiss with `SQLX_OFFLINE=true`; tag
`v0.7.0` and the GitHub release carry the changelog section.
