# 0.4.1 crates.io release

- **When:** 2026-10-10 15:59:57 local
- **Type:** execution
- **Project:** chaiss

## Context

Patch release carrying CHAI-0044 (PR #60): forward tolerance for
databases migrated by a newer chaiss (ADR-0001), explained open
failures instead of a panic, migration tests against real SQLite
files, and the README developer note on building with `DATABASE_URL`
set. Cut before CHAI-0045 so published users get the hardening first.

## Details

Release PR #61 bumped `chaiss` and `chaiss-core` 0.4.0 → 0.4.1 in
lockstep and promoted the Unreleased changelog section; patch bump,
fixes only, no public API change. Pre-merge, the chaiss-core dry-run
passed against the crate-local `.sqlx` cache and the chaiss dry-run
failed only on the not-yet-published dependency, as expected.
Published from a synced main in dependency order with
`SQLX_OFFLINE=true`: chaiss-core first, confirmed available, then
chaiss. Annotated tag `v0.4.1` on the merge commit; GitHub release
created from the changelog section with crate links. No cache
regeneration was needed, since CHAI-0044 added no checked queries.

## Lesson

The forward-tolerance fix protects 0.4.1 and later. Users on older
builds who open a newer database still hit the old panic until they
upgrade; there is no publishing-side remedy for binaries already
installed.
