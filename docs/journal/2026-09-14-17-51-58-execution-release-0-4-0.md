# 0.4.0 crates.io release

- **When:** 2026-09-14 17:51:58 local
- **Type:** execution
- **Project:** chaiss

## Context

Minor release bundling the model-selection arc: the chat-pane model
selector (CHAI-0040, PR #53), GPT-6 Astra as the OpenAI default plus
the reasoning-model temperature fix (CHAI-0041, PR #54), literate cola
configuration via `.chaiss.cola` (CHAI-0042, PR #55), and per-game
persistence of the last-used model (CHAI-0043, PR #56).

## Details

`chaiss` and `chaiss-core` bumped 0.3.2 → 0.4.0 in lockstep — a minor
bump, since the release adds features and changes the `chaiss-core`
public API (new `LlmProvider`/`LlmTarget`/`cola_config`, and
`LlmPromptPayload` now requires a `target` field). Release PR #57
carried the version bumps and the `## [0.4.0]` CHANGELOG section.

The first `chaiss-core` publish failed verification: `cargo publish`
compiles the packaged crate standalone, against the `.sqlx` cache
bundled inside the crate directory — which `cargo sqlx prepare
--workspace` does not update (it writes the workspace-root cache
only). PR #58 regenerated `chaiss-core/.sqlx` crate-locally against
the migrated scratch database, and the `v0.4.0` tag was re-pointed to
that merge commit (`d650760`) before publishing — no GitHub release
existed on the old tag yet — so the tag matches the published tree.

Published from a synced main in dependency order with
`SQLX_OFFLINE=true`: `chaiss-core` first, then `chaiss`, whose
pre-publish verification compiled against the registry copy of
`chaiss-core` 0.4.0. GitHub release created on the tag with the
CHANGELOG-derived notes and crate links.

## Lesson

After adding sqlx queries, run `cargo sqlx prepare` *inside*
`chaiss-core` — the crate-local cache is what ships in the package —
not only `--workspace`. A pre-release `cargo publish --dry-run -p
chaiss-core` catches this class of failure before the tag moves.
